# Инструкция агенту: реализация Mixor

## Источник задания

Сначала прочитай [SPECIFICATION.md](SPECIFICATION.md), затем весь связанный комплект в `docs/`: VISUAL_AND_AUDIO, ASSET_PRODUCTION, CONTENT_AND_MAPS, ARCHITECTURE, DATA_AND_API, IMPLEMENTATION_PLAN и SOURCES. Этот файл не заменяет подробные требования.

На момент спецификации 0.2 в репозитории находится документация, а не готовое приложение. Перед изменениями проверь фактическое состояние: другой агент мог уже начать реализацию. Сохраняй существующую полезную работу, не перезаписывай файлы и историю без необходимости.

## Главная цель

Создать семейную образовательную игру-исследование о миксомицетах и амёбоидных существах. Технически это PWA на JavaScript/TypeScript, но визуально — цельный полноэкранный исследовательский мир с крупными реальными фото, атмосферной музыкой и звуковыми эффектами.

Нельзя считать задачу выполненной, построив стандартный dashboard, форму загрузки и несколько карточек. Качество художественной подачи — отдельный критерий приёмки наравне с надёжностью хранения.

## Порядок работы

1. Проверь repository state, актуальные поддерживаемые версии зависимостей и ограничения платформ. Выбери указанные в спецификации defaults; неизвестный возраст ребёнка, модель планшета и будущий AI-provider не должны блокировать локальный игровой срез.
2. Реализуй этапы 0–1 из IMPLEMENTATION_PLAN: воспроизводимый local demo, сцены входа/базы/портрета, реальные разрешённые изображения, работающий AudioManager, fullscreen fallback, цикл/исследовательское действие. Не начинай с одного только backend.
3. Реализуй этап 2: отдельные семейные аккаунты, локальные drafts/blobs/outbox, private S3, Lambda/API/DynamoDB, синхронизация телефона и планшета, семейная карта, экспорт.
4. Расширь до этапа 3: подготовленный атлас, карты мира/Германии, контентные квоты, все основные сцены, полноценные audio и acceptance tests.
5. Поздние AI/3D/симуляцию/скачиваемые карты не смешивай с обязательным первым выпуском. Если среда не позволяет deploy, заверши доступный локальный/тестируемый результат и точно укажи, что осталось без развёртывания.

Это порядок исполнения, не требование автоматически останавливаться после каждого пункта за новым подтверждением. Существенные отклонения фиксируй в ADR и обновляй связанные контракты.

## Непереговорные правила

- Реальные фото обязательны; схемы и сгенерированное оформление маркируются. Не придумывай лицензии, источники, масштаб, стадии, координаты, современные таксономические связи или результаты определения.
- Музыка и эффекты входят в ранний игровой результат; звук только после действия пользователя, с mute и корректной паузой. Silent/reduced-motion режим полноценен.
- Неизвестный вид и неизвестное место допустимы. Фото, импортированное дома, не получает домашние координаты автоматически. Никакого принудительного определения до вида.
- Сохранение сначала локально и с реальными blobs. Не сообщай «сохранено в облаке» на основании локального mock или отправки незавершённого файла.
- Два аккаунта — не один пароль с переключателем персонажа. Все права и принадлежность семье проверяются на сервере, включая media/jobs/exports.
- Репозиторий публичный. Не коммить семейные снимки, EXIF/точные семейные координаты, секреты, токены, подписанные URL и архивы приватной коллекции. Используй явно синтетические fixtures.
- Оригиналы, история определений и неотправленные правки не уничтожаются тихо. Конфликты, повторные события, expiry и обновления должны быть покрыты тестами.
- Внешние находки не равны полному ареалу; домашние культуры не считаются дикими. Классификация и жизненный цикл — разные структуры.
- Публичный OSM tile server не использовать для запрещённого массового offline-download. Авторство фото/музыки/карт видно и соответствует конкретным условиям.
- API, validation и domain types проектируются с начала, используются самой игрой и документируются OpenAPI. Не связывай их напрямую с конкретным renderer.

## Техническая дисциплина

TypeScript strict, runtime validation входных данных, маленькие предметные модули, типизированные ошибки, отмена неактуальных запросов, cleanup ресурсов сцен/аудио. Достаточный выбранный стек — React/Vite + SVG/Canvas/DOM; более тяжёлый движок требует аргумента.

Локальный запуск должен работать без AWS credentials. Production auth bypass запрещён. Версии зависимостей фиксируются lockfile; секреты только в разрешённом серверном хранилище/деплое. Cloud ресурсы описываются кодом, private media не раздаются через публичную статику.

Проверки: unit/integration, контракты, E2E, content/assets validation, role/security tests и художественный review. Команды запуска/build/test и рабочие ограничения документируются. Не сообщай об успешном запуске теста, которого не выполнял.

## Результат каждого завершённого этапа

Рабочий сквозной сценарий, commit с понятными изменениями, актуальные схемы/документы, тестовый отчёт и screenshots ключевых экранов телефона/планшета. Для звука требуется реальная проверка воспроизведения: автоматический тест вызова `play()` не заменяет прослушивание качества петли.

Отдельно перечисляй: реализовано; проверено автоматикой; проверено на физическом устройстве; осталось непроверенным; ещё не реализовано. Не называй локальную демонстрацию готовым AWS deployment. Не называй список URL готовым медиапакетом.

Главный критерий: ребёнку хочется исследовать настоящий микромир, а родитель может доверять сохранности, общему доступу в семье и научной честности найденного материала.

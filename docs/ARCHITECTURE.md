# Архитектура, AWS и эксплуатация

Версия 0.2 · Проектное решение для реализации. Ничего в этом документе не означает, что инфраструктура уже создана. [API и данные](DATA_AND_API.md) уточняют контракты; [источники](SOURCES.md) фиксируют основания платформенных ограничений.

## 1. Архитектурная цель

Один клиентский игровой мир на телефоне, планшете и компьютере; локально надёжная полевая запись; общий приватный семейный backend; оплата облачных операций преимущественно по использованию; возможность пользоваться через месяцы перерыва без работающего круглосуточно сервера.

Не смешивать доменную модель с рендерером сцены. Замена Canvas на другой renderer не должна менять наблюдение, права или API. И наоборот: прототип с локальным adapter должен демонстрировать те же сценарии, что облачная версия, не выдавая локальные данные за синхронизированные.

## 2. Предлагаемый стек

| Область | Базовый выбор | Ограничение |
|---|---|---|
| Клиент | React + TypeScript, Vite | Актуальные совместимые версии и lockfile фиксируются агентом |
| Сцены | DOM/CSS + SVG + Canvas 2D для отдельных эффектов | Не делать весь интерфейс недоступным canvas |
| Дерево | SVG, при необходимости алгоритмы раскладки D3 | Классификация хранится отдельно от координат раскладки |
| Карта | Leaflet и сменный provider подложки | Лицензии и офлайн-условия отдельно от библиотеки |
| Локальные данные | IndexedDB через небольшой проверенный wrapper | Хранить blobs, а не только временные object URLs |
| Звук | Один AudioManager, Web Audio/HTMLAudio под общим adapter | Лицензированные реальные дорожки, обработка autoplay |
| Сборка/раздача | Static build → приватный S3 origin → CloudFront | Только код и публичный учебный контент |
| Вход | Cognito User Pool, authorization code + PKCE | Отдельные аккаунты, закрытая регистрация |
| API | API Gateway HTTP API + Lambda | Проверка токена и семейных прав |
| Метаданные | DynamoDB Standard, on-demand | Семейные partition/query, без таблиц фотографий в JSON |
| Приватные медиа | Отдельный S3 bucket | Private originals, previews, exports |
| Обработка | S3 event → SQS → Lambda worker + DLQ | Идемпотентность, version pinning, предел попыток |
| Инфраструктура | AWS CDK на TypeScript | Воспроизводимые dev/prod настройки, без секретов в Git |
| Проверки | Unit/integration + browser E2E, например Vitest/Playwright | Конкретные версии перепроверяются при старте |

PixiJS допустим через ADR, если первая сцена доказала необходимость более сложного 2D renderer. Three.js и полноценная 3D-сцена — не начальная зависимость. Игровое ощущение не требует ECS, физического движка, глобального render loop для форм или собственного движка с нуля.

## 3. Компонентная схема

```text
Телефон / планшет / компьютер
  ├─ игровой UI + фото + дерево + карта + AudioManager
  ├─ domain stores + локальные snapshots
  └─ IndexedDB: drafts / outbox / blobs / prepared content
           │
           ├─ Cognito login (code + PKCE)
           ├─ HTTPS API → API Gateway JWT → Lambda → DynamoDB
           └─ разрешённая прямая загрузка → PRIVATE S3
                                                   │
                                             S3 event → SQS → image worker → DLQ
                                                        │
                                                        └─ variants + media state + change event

CloudFront ← S3 app/public-content: только разрешённый открытый контент
ExternalSourceAdapter → GBIF: ограниченные публичные запросы и кэш
Future AI worker → отдельный provider: только после согласия взрослого
```

CloudFront OAC защищает S3 origin, но не является авторизацией семьи. Не размещать приватные фотографии под публичным CloudFront behavior. См. S24.

## 4. Предлагаемая структура кода

```text
apps/web/src/
  app/                 # routes, scene shell, auth boundary, settings
  scenes/              # entrance, base, atlas, tree, cycle, map, journal
  features/            # capture, comparison, identification, progress
  rendering/           # effects and renderer adapters
  audio/               # one lifecycle-managed AudioManager
  offline/             # IndexedDB, outbox, sync, migration, cache policy
services/api/          # thin handlers, authz, application services
services/workers/      # images, exports, future identification
packages/domain/       # framework-independent types/invariants/use cases
packages/contracts/    # runtime validation, OpenAPI, generated client
packages/content/      # taxon records, cycles, tasks, source references
content/               # asset manifest, prepared public content metadata
infra/                 # CDK, policies, stages, bootstrap scripts
scripts/               # content/media preparation and maintenance
 tests/                # shared fixtures where appropriate
```

Пробел перед `tests/` в схеме не является частью имени каталога. Точная структура может быть упрощена; не создавать monorepo-пакеты без реальной границы ответственности. При любом варианте локальная демонстрация запускается документированной командой без AWS-ключей.

## 5. Клиентские границы и состояние

`SceneRouter` управляет пространством и восстановлением контекста. `ObservationRepository` имеет local/mock и cloud реализации. `SyncService` отправляет операции и принимает изменения. `MediaService` занимается файлами и загрузками. `ContentRepository` выдаёт версионированный публичный справочник. `ExternalOccurrenceProvider` нормализует внешние записи. `AudioManager` живёт выше отдельных сцен.

Бизнес-операция «сохранить наблюдение» не зависит от окончания анимации или готовности музыкального файла. У каждой сцены отдельный error boundary; ошибка карты/видео не рушит локальную очередь. Маршрут конкретной записи сохраняется при login redirect и возвращается после входа.

Декоративная анимация не использует React state для каждого кадра. У effects есть start/stop/dispose; текстуры, AudioNodes, observers, listeners и object URLs освобождаются. При смене сцены отменять неактуальные fetch и не показывать их запоздалые результаты.

## 6. Аккаунты и семейная авторизация

Первого взрослого создаёт bootstrap-процедура оператора, не публичный endpoint с возможностью назначить себя родителем. После входа взрослый создаёт/подключает детский аккаунт через административный серверный маршрут. Доставка первичных данных входа и смена временного пароля проверяются отдельно. Детский пользователь может использовать псевдоним/username без собственной почты; конфигурация Cognito не должна делать email обязательным для него.

Браузерный app client без client secret, code flow с PKCE S256, проверкой state и callback allowlist. Implicit flow не включать. Документированные возможности Cognito — S18.

API Gateway проверяет issuer, audience/client и срок токена; маршруты требуют подходящих access scopes. В Lambda дополнительно проверяются `token_use=access`, членство, роль и принадлежность каждого объекта семье. `familyId`, `role`, `createdBy` из тела клиента не считаются доверенными. Особенности JWT authorizer — S19.

В MVP один пользователь состоит в одной активной семье. Endpoint `/v1/me` возвращает разрешённую семью, роль и capabilities. Расширение на выбор нескольких семей позже не должно ослаблять изоляцию.

Сессионные секреты не хранятся в доменной IndexedDB вместе с фото. Использовать проверенную OIDC-библиотеку и явно описать token storage/refresh policy. Базово не класть долговременный refresh token в общедоступный localStorage; «доверять устройству» — осознанная отдельная настройка с документированным риском и ограниченным сроком. Приложение не хранит пароль. CSP, отсутствие небезопасного HTML и контроль зависимостей обязательны независимо от storage.

Истёкшая сессия не удаляет уже сохранённый локальный черновик. Вне сети ранее выбранный профиль может продолжить локальную запись, но это не новый серверный вход и не право получать чужие облачные данные. Новый аккаунт нельзя аутентифицировать без связи.

Отзыв членства прекращает новые API-доступы. Уже сохранённые локальные копии и ранее выданные короткоживущие ссылки невозможно честно объявить мгновенно исчезнувшими: это ограничение отмечается в модели угроз. Logout очищает приватные кэши после обработки неотправленных черновиков; публичный контент можно оставить.

## 7. Загрузка фотографии

### 7.1. Клиентский путь

Оригинальный File принимается без изменения. В worker/асинхронно извлекаются доступные EXIF и создаётся временное превью. Предложения координат и даты показываются пользователю, не перезаписывая его подтверждение. Оригинал и draft сохраняются локальной транзакцией. Только после успешного завершения транзакции разрешено показать «На этом устройстве».

При восстановлении сети сначала создаётся observation metadata, затем media records и upload sessions. Передача идёт прямо в private S3, не через body Lambda. API возвращает ограниченный upload grant после повторной авторизации. См. S20.

Начальные конфигурируемые лимиты: 25 MiB на файл, 20 файлов на наблюдение, декодированный размер до 80 мегапикселей. Это проектные настройки, которые пересматриваются после теста реальных телефонов; сервер проверяет их независимо от клиента. Для больших размеров нельзя молча сжимать единственный оригинал — объяснить ограничение и сохранить локальный исходник для экспорта.

MVP требует JPEG/PNG. HEIC/HEIF на реальных целевых телефонах — release gate: либо рабочий проверенный путь конвертации и просмотра с сохранением оригинала, либо явно описанное ограничение без потери файла. RAW, произвольные SVG и пользовательское видео не принимать как будто это обычный JPEG.

### 7.2. S3 и обработчик

Ключи генерирует сервер: `families/{familyId}/uploads/{mediaId}/{attemptId}/...`. Оригинальные имена пользователей не служат путями. Bucket private, Block Public Access включён, CORS ограничен клиентским origin. Upload grant имеет короткий TTL, привязку к ключу/типу/размеру в пределах выбранного механизма; точная enforceable policy покрывается тестом, а не только текстовым обещанием.

Подписанный URL не считать одноразовым сам по себе. S3 допускает повторное использование действующего разрешения; повтор/перезапись и версия объекта должны быть учтены. Bucket versioning или перенос проверенного объекта на новый immutable key фиксирует именно принятые байты. Worker читает конкретный versionId и проверяет checksum, а не произвольный «последний объект по этому ключу». ETag не считать универсальным MD5.

S3-события обрабатываются как повторяемые и потенциально приходящие не по порядку. Возможности destinations описаны в S21. Queue содержит mediaId, upload attempt и version information, но не весь файл или EXIF. Worker сверяет действующую запись, размер, magic bytes, декодирование, лимиты ресурсов и checksum. Не открывать произвольные внешние URL из изображения.

Только обработанный доверенный preview доступен inline. Сомнительный файл остаётся quarantined/rejected, оригинал не публикуется. Аннотации хранятся отдельно. Ориентация нормализуется для производных, связь с оригиналом сохраняется. Из превью удаляются GPS и ненужные EXIF; семейные координаты остаются в приватной записи.

Выходные префиксы `originals/` и `variants/` не триггерят тот же обработчик входных `uploads/`. Каждая версия pipeline идемпотентна. Worker перед финальным commit проверяет, что наблюдение не удалено и media не отменено; иначе не воскрешает его. Неудачные задачи после ограниченного числа попыток попадают в DLQ с понятным статусом в приложении.

### 7.3. Чтение и очистка

Просмотр: API проверяет доступ, возвращает короткоживущий GET grant на конкретный variant/version. Не хранить подписанный URL как постоянное поле наблюдения. Не логировать query подписей. Наличие известного mediaId не даёт права читать объект.

TTL чтения ориентировочно 5 минут, загрузки 10 минут как конфиг. При истечении обновить grant; оригинал не потерять. Заброшенные upload attempts чистятся отдельной ограниченной задачей; не удалять оригинал, на который ссылается готовая запись. Local blob можно освободить только после подтверждения принятых сервером байтов и при заданной политике кэша, не сразу после HTTP 200 на upload.

## 8. Offline-first и синхронизация

IndexedDB хранит snapshots, операции outbox, оригинальные blobs, привязку пользователя/семьи, content manifest и cursor. Поддержка структурированных данных и файлов — S26. Cache Storage для shell/public assets отделён от приватного хранилища. Wildcard service worker не должен кэшировать Authorization-запросы и presigned responses в общий публичный кэш.

Сначала локальная транзакция, затем отправка. Статусы метаданных, байтов и серверной обработки независимы. При квоте/ошибке записи показывать отсутствие подтверждённого сохранения и действие «Экспортировать/освободить место». Не обещать вечную сохранность браузерного storage; запрашивать persistent storage где доступно, но учитывать отказ. S04–S05.

Одновременно до двух медиа-upload как стартовая настройка; метаданные и зависимости сериализуются по сущности. Повторы с exponential backoff/jitter, без бесконечного retry для 400/403. 401 приостанавливает отправку до повторного входа. 409 требует разбора конфликта. Подписанный expired grant перевыдаётся, а не создаёт новое наблюдение.

`navigator.onLine` — подсказка, не доказательство доступности API. Возобновление при запуске, возврате вкладки и явном «Синхронизировать». Background Sync — только дополнительное улучшение, не гарантия отправки закрытой PWA. На телефоне пользователь видит, сколько записей/фото осталось только здесь.

Сервер выдаёт последовательный change cursor; детали атомарных событий и resync — в DATA_AND_API. Часы устройства не используются как единственный watermark. Удаления — отдельные события. Одновременная правка не молча затирает вторую версию. Независимые заметки append-only упрощают объединение.

Обновление service worker не делает unconditional `skipWaiting`/reload при черновиках. Миграция IndexedDB транзакционна, протестирована на старой очереди. Старый несовместимый клиент получает требование обновиться, сохраняя возможность экспортировать локальное. Публичный content cache можно обновлять независимо от приватных данных.

## 9. Данные и запросы

DynamoDB хранит metadata, не байты фото. Partition key включает семью; индексы для её записей никогда не превращаются в глобальный Scan. Для небольшой коллекции допустимо загрузить пагинированный набор компактных семейных координат и группировать на клиенте; отдельный геопространственный кластер не нужен.

Запись доменной операции, change event и idempotency record должна быть атомарной. Начальная схема использует TransactWrite с условным обновлением семейного revision; возможность транзакций и их ограничения описаны в S25. Конкретные ключи и алгоритм — в DATA_AND_API.

Публичный справочник — версионированные файлы/manifest, не копия текста на каждую семью. Внешний occurrence cache хранится отдельно, с источником и TTL. Задачи над семейными данными не кладутся в общий публичный cache.

## 10. Сеть, безопасность и приватность

HTTPS в production; ограниченные CORS origins; CSP; безопасные response headers; escaping/sanitization импортированного HTML и пользовательских заметок. EXIF, изображения, научные страницы и будущий AI-output считаются недоверенным вводом. Не выполнять текст из метаданных как инструкцию, код или URL скачивания.

Проверять принадлежность `observationId`, `mediaId`, `jobId`, `seriesId` одной доступной семье. ID не являются защитой. Все privileged actions защищены серверной ролью, а не скрытой кнопкой. Тестировать IDOR, подмену familyId, доступ к оригиналу после logout и public bucket policies.

Секреты AWS/AI — только server-side secret storage или механизм развёртывания. Не встраивать их в Vite env, открытый Git, screenshot или экспорт. Предпросмотр PR не получает production-семейные данные. Нельзя включать production auth bypass через переключатель интерфейса.

Public demo fixtures полностью вымышленные и помеченные. Логи не содержат координат, фотографий, EXIF, полных заметок, access/refresh tokens и подписанных URL. Для диагностики достаточно requestId, типа операции, непрямых ID, длительности и code ошибки.

AWS region по умолчанию `eu-central-1`, но отдельно описываются регионы резервирования, глобального CDN и внешних AI/карт. Размещение основной базы в ЕС само по себе не является сертификатом соответствия всем законам. Публичные публикации и AI-disabled по умолчанию.

## 11. AI-модуль позже

Provider adapter server-side, capability flag, взрослое согласие, квота и асинхронный job. На анализ отправляется специально подготовленная копия без GPS/ненужных деталей, а не URL на весь приватный альбом. Никаких фоновых анализов при каждом открытии фото.

Job сохраняет provider/model/version, входные media versions, параметры, дату, кандидатов и ограничения. Output — недоверенная структурированная гипотеза, не готовое определение. Валидация ответа не позволяет модели обращаться к чужим объектам или менять права. Доступность функции и выбранный provider не требуются для выпуска остального продукта.

## 12. Экспорт, корзина и резервирование

Экспорт взрослого создаёт job, manifest JSON, GeoJSON, историю, связи и оригиналы. Большие объёмы допускают manifest + несколько архивов, а не обязательный гигантский ZIP в памяти Lambda. Контрольные суммы и версия схемы позволяют восстановление. Временный экспорт private, удаляется по политике, например через 24 часа.

Soft delete синхронизируется сразу. Предлагаемая корзина 30 дней; окончательное удаление затрагивает originals, versions, variants и exports, а lightweight tombstone может оставаться для предотвращения воскрешения старым клиентом. Настройка времени согласуется с политикой резервных копий и документируется.

Включить подходящее резервирование DynamoDB и S3 versions с ограниченным сроком; не считать versioning единственным протестированным backup. Перед семейным выпуском выполнить восстановление тестовой коллекции в изолированную среду. После восстановления повторно применить журнал удалений, чтобы не вернуть уже удалённые приватные данные. Реальные RPO/RTO фиксировать по конфигурации и тесту, не придумывать SLA.

## 13. Стоимость и редкое использование

Обычные Lambda on-demand, DynamoDB on-demand, S3 и статическая раздача. Не использовать EC2, RDS, NAT Gateway, provisioned concurrency или постоянно работающий GPU без отдельного доказанного требования. Runtime выбирать из поддерживаемых AWS при реализации, см. S22.

Стоимость включает хранение оригиналов/версий/экспортов, обработку/выдачу, API, Cognito, карты, домен, логи и позднее AI. Оплата по использованию не означает отсутствие платы в месяцы без входов. Проверять актуальные тарифы S27–S30, не обещать бесплатность навсегда.

Сделать cost worksheet для трёх собственных сценариев: прототип, одна активная семья, выросший альбом; фиксировать входные предположения и дату тарифов. Пример объёма: 1000×6 MB ≈ 6 GB оригиналов до превью и копий; это арифметика объёма, не оценка счёта.

Ограничить upload size/count, worker concurrency, retries, API rate, log retention и AI budgets. AWS Budgets — уведомление, не гарантированный жёсткий потолок расходов, см. S23. API-квоты приложения важнее обещания «serverless не может дорого стоить».

Не опрашивать внешние источники постоянно без пользователей. Периодические maintenance/backup задачи должны быть редкими и ограниченными. Логи начально 14–30 дней, abandoned uploads и exports очищаются, indefinite retention не включать случайно.

## 14. Развёртывание и сопровождение

Dev/demo без AWS и cloud dev/prod — разные режимы. Первый локальный запуск не требует облачного аккаунта; mock mode заметен. Перед production сборкой проверять отсутствие demo auth bypass, секретов, fake occurrence records и неутверждённых ассетов.

CI: typecheck, lint, tests, content/asset validation, build, contract validation и infrastructure synth/security assertions. Деплой в production явно отделён от PR preview. Использовать ограниченные временные deployment credentials, не записывать постоянные ключи в workflow.

Backend/API и клиент поддерживают согласованный период совместимости; versioned static assets позволяют rollback. В deployment runbook описать initial parent bootstrap, child enrollment, CORS/callback URLs, domain, monitoring, backup restore, migration, secret rotation и удаление тестовой среды без затрагивания production.

Serverless уменьшает обслуживание серверов, но не отменяет обновления зависимостей, runtime, доступов и проверку восстановления. Документировать владельцу минимум необходимых операций, не выдавая все AWS admin-права детскому аккаунту.
